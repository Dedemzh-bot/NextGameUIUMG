# Explicit delegated appearance choices

`delegated-art-choice/1` is an opt-in compatibility contract inside the existing art pipeline, not a new screening command. It applies only when the original direct user request explicitly delegates the current test and includes the art stage. It does not turn an ordinary continuation, a method preference, or an earlier UI acceptance into authority.

The request declares this capability together with `presentation-review/1`, and binds a closed `delegatedArtChoice` sidecar. That sidecar binds the original RequestPacket and authorization record, the exact message hash, the current request and exact asset scope, and individually chosen text appearance records. The accepted requirement must retain the same input digest and original message. The initial registered grant wording is the exact Chinese phrase in the schema; unsupported wording requires explicit future compatibility, not an inferred match.

The schema also registers the complete explicit sentence `我授权本次测试按插件现有支持的委托审核流程自动推进；委托审核不能替代真实验证或伪造通过。`. It must occur in the unchanged original direct-user message together with `高保真美术还原`, under the same request and all existing source and scope checks. This narrowly defined compatibility does not recognize a bare `执行`, a method preference, or inferred consent. It does not change existing grants, source confidence, actual visual evidence or the independent result-review gate.

A text uses `resolution: delegated` only when its complete reference, reason, effect, confidence, outline and shadow fields equal the bound coordinator choice. `confirmations` remains empty. Source-identification confidence remains medium/low when appropriate; delegation never promotes it to high. Unknown/unmade choices cannot enter this path.

This permits applying explicit reconstruction choices under the user's delegation. It does not establish the original art tool's numeric parameters, make an uncertain source unambiguous, or accept the resulting image. Actual property agreement, canonical context-bound captures, individual region inspection, measured geometry, hidden states, wider/taller viewports and final stage validation are unchanged. Result acceptance and documentation continue through their separate contracts. Legacy requests retain their prior strict interpretation.

Adopt through a new bound request and decisions revision; preserve the original request, choices and execution evidence. The sidecar is a transparent local provenance record, not a cryptographic authentication of a chat message.
