# Independent measured presentation receiver

This unpublished narrow receiver adds `nextgame-ui-measured-geometry-adoption/1`
for one completed flat static item-pilot Art execution. Adoption is a read-only
verification extension. It does not alter the original request, decisions,
plan, completed checkpoint or saved asset, and never creates a substitute
execution. Legacy request, capture/1 and verification/1 definitions are unchanged.

The narrow Retainer/native Blueprint VM consumer is implemented from actual
retained production run-1 inputs. This isolated source stage has not published
a package or emitted a canonical capture/verification. A capability probe is
never upgraded. Python FGeometry zero values remain diagnostics; the geometry
source is actual VM paint LocalSize and four LocalToAbsolute returns.

## Freeze adoption before collection

Prepare one closed `measuredGeometryAdoption` document using the schema. Bind
actual existing request, decisions, plan, completed execution and its exact
readback as `finalSnapshot`, plus immutable collector/helper source and saved
Font/Face readback and actual OS `hostEvidence`. Each binding is exactly `{path,sha256}`. Include at least
one actual helper/topology source; duplicate paths or collector-as-helper are
rejected. Adoption has its own actual `createdAt`, after completed apply and
before the real collector interval. Do not bind future raw, PNG or geometry
outputs in adoption. A source/helper change requires a new adoption revision.

`configuration` identifies the explicit project, original referenceId, four
native receivers, content root/design basis and producer
`euw-retainer-nativevm/1`. Cases are exactly unit scale followed by whole-instance
0.75 with distinct IDs. No geometry capability or configuration is inserted
into the original request. The original reference's size, locale, state/data,
font digest, background and source/capture mapping remain authoritative.

For the current pilot the existing request requires transparent 129x129 at
DPI1, zh-CN, quantity-1, standard/default; the full 101 source maps to
`[14,14,101,101]`. These are requirements, not observed producer measurements.
No resize, crop, relabeling of an arbitrary target, desired size or Slot/padding
arithmetic may stand in for native arrangement/capture evidence.

## Narrow native producer contract

The closed `retainerGeometryRaw` envelope binds adoption, executed collector,
helpers, exact final snapshot, physical source package and before/after hashes,
complete native `loadedSnapshotBefore/After`, their raw acquisition receipt,
and two case records. Each case binds its original PNG, native producer,
geometry and runtime readbacks, actual frame/time, instance/Retainer/target,
font evidence, controlled context and whole-instance scale.

Provider, paint, runtime identity/getter, loaded-snapshot and host/helper
documents have closed schemas matching actual retained data. Vendor getter
envelopes are re-normalized through a transport that only matches retained
responses; it dispatches no Tool and executes no archived or returned code.
The consumer recomputes these facts instead of trusting derived corners or
pass flags:

- Actual EUW -> Retainer -> capture canvas -> pilot/receiver topology, native
  helper function/graph source, same PID/project/world, and actual target export
  association. The EUW host's large allocation is distinct from the fixed target
  and96-pixel pilot. No Actor/WidgetComponent or startup-script flag is required.
- VM `GetPaintSpaceGeometry` LocalSize and four LocalToAbsolute results for
  target canvas and each real receiver. Actual native target mapping converts
  absolute corners to pixels. No cached-geometry claim is made by this route.
- Complete loaded asset state equal to final execution snapshot, and actual
  runtime Brush/text/font/slot/visibility/local transforms equal to that source
  except the single approved whole-instance preview scale. Asset templates do
  not prove the properties of a rendered runtime clone.
- The same real pilot/Retainer/target and receiver identities in both cases,
  unit before0.75 on later real frames, and completed redraw before each export.
  Original image-local101/96 scale remains unchanged across the cases.
- Exact actual target RTF_RGBA8, sRGB=false, targetGamma1, transparent clear
  color and `RenderingLibrary.export_render_target`. Decode little-endian
  float32 RGBA byte-values, require finite integral0..255 channels, recompute
  channel extrema and compare every PNG byte. This verifies export identity,
  not perceptual similarity. No WidgetComponent `applyGammaCorrection` exists
  in this backend contract.
- Exact Font/Face packages, TTF bytes, dependency edges and actual receiver
  font/text/context. The backend does not accept a guessed typeface name.

## Late read-only binding

After actual collection, use new paths outside the plugin:

```powershell
python -B scripts/art_geometry.py --adoption "<frozen-adoption>" --collector-raw "<actual-raw>" --geometry-output "<new-sidecar>" --output "<new-capture2>"
```

The binder reloads the exact original completed execution and all bindings. It
may preserve a new immutable input sidecar when later validation fails; that
sidecar is not a success receipt. It writes no capture until the provider
interpretation and every actual constraint pass. Missing or changed inputs
are rejected; no expected geometry is supplied to fill them.

## Verification and final independent stage

The normal read-only command accepts the separate binding explicitly:

```powershell
python -B scripts/art_pipeline.py verify "<original-plan>" --execution "<original-completed-execution>" --captures "<capture2-list>" --geometry-adoption "<frozen-adoption>" --output "<new-verification2>"
```

It must accept exactly the original reference once and only capture/2 on the
adoption route. A missing adoption cannot accept capture/2; old capture/1 cannot
be promoted into measured evidence. The geometry sidecar and verification/2
must identify the same adoption, final snapshot and actual case mappings.
Verification2 retains the original plan/execution bindings.

`validate_art_stage` reloads that verification's exact adoption binding and
reruns the same lineage, source/helper/font, raw/PNG, loaded-state and provider
checks independently. It then compares deterministic presentation checks and
exact geometry-sidecar coverage. It trusts neither a canonical label nor a
previous passed status. Only that recomputed proof may close matching preserve
image geometry; planned checks remain unchanged. Visual review must cover the
normal comparison regions and both `geometry:<caseId>` views after collection.
Final Bundle/readback and later user result acceptance remain separate gates.

Static stage validation covers AST/schema structure, unchanged legacy/request
contracts, the exact8-file allowlist and reconstruction of the original r2 plan.
The original authority location passes full validation; an isolated copy
retains the original absolute-path refusal and independently reconstructs the
same plan with authority checking excluded only for that static comparison.
The original four authority source bytes are unaffected. Publication requires
a fresh full validation at the original location.

Actual run-1 provider inputs were separately recomputed without new Editor
calls. Four native asset reads bracket the two exports; the runtime and
asset-before reads may overlap, but both must finish before the VM paint/export
for that case. Source changes are not used to rewrite acquisition chronology.
New verification/2 passed bytes are emitted only after in-memory independent
stage revalidation, and its persisted record is rechecked again. No tests,
Editor calls, production rendering, final acceptance or publication are
performed by this source proposal.
